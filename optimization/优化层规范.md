# 优化层规范（最小集）

2026-10-31（第一版，未实现；取代已撤销的策略层）。优化层在 `optimization/`。它读规则层（`rule/`，见 `rule/规则层规范.md`）的函数和事实输入，产出一组落盘的中间产物：图、标签前沿、路径、分支、税额表、排序、差额、未决项。规则层不依赖优化层；优化层不依赖任何调用者。

**语言**：本规范用中文，供人阅读；英文副本 `optimization/optimization_layer_spec.en.md`，两者不一致时以中文版为准，改中文版时同步改英文副本。AI 写进文件的一切自写文字用英文——代码、注释、工具说明、prompt（系统实际递交的是英文副本里的那段）、底稿、核对单、handoff、bug 反馈、日志、产物字段；原件、条文、引文、客户原话保持原文，不翻译。唯一例外是给客户看的文字（对客户的回话、briefing）跟客户的语言。核对单的总判断用英文记号：交接包 `RUNNABLE` / `REVISE`，报告 `DELIVERABLE` / `REVISE`（服务也接受原来的中文记号）。

## 0. 功能定位与范围

优化层和规则层一样，为 AI agent 提供逻辑、计算上的程序化辅助，帮忙缓解幻觉和上下文限制：它把"这笔股息在库里的法律下有哪些走法、各自税负区间多少、差在哪、还差什么才能确定"算出来并摆在桌上，agent 读产物，不自己搜路径、不自己算税。它只提供铲子，不做判断，不规定怎么用。它保证的只有一件事：**同样的输入永远得到同样的产物，产物里的每个数都能回到规则层的输出项，再回到条文**。

| # | 功能 | 用处 | 落实 |
|---|---|---|---|
| 1 | 建图：法域 × 主体为节点，一跳股息流为边，边权由规则层现算，终点集合由背景给出 | 把"走法"变成图上的路径 | §4.1、§4.4 |
| 2 | 最短路：带资源约束的多标签 label-setting，返回到终点集合的非支配前沿 | 不漏、精确、随规模长大 | §4.2–4.3 |
| 3 | 分支：前沿路径上未答的判断点按 yes / no 展开，答案以假设标注 | 假设可见 | §4.6 |
| 4 | 目标、排序、差额与未决项：每次付款的税，按有利侧排序（等于相对基准每次省多少）；重组的一次性成本（转让所得税 + 印花税，个人迁居另加离境税）单算，回本次数 = 一次性成本 ÷ 每次省的税，只在税相同时排先后；同一组判断答案下比较全部结构（情景表），哪些未决项会换掉第一名 | 可比，知道该问什么、每次省多少、几次回本 | §4.5、§4.7 |
| 5 | 产物：全部中间结果落盘，带版本和出处；按需评价任一指定路径、每条路径的执行要件、两轮产物的差异 | agent 和报告只读，问"经日本走呢"也有同格式的答案 | §4.10、§5 |
| 6 | 校验：不变量、穷举基线、金标、回溯 | 铲子本身不坏 | §7 |

去掉的、不必要的：元启发式搜索（问题是精确可解的）；问题的代价模型；谓词答案的概率；多目标（目标只有税，区间的两侧不是两个目标；一次性成本不是第二个目标：它只通过回本次数给税相同的结构排先后，2026-11-04 用户定）；持有年限与 N 年总税（不问客户持有多久，回本按次数给出，2026-11-04 用户定）；折现（回本次数不折现，2026-11-04 用户定）；估值（对价取输入的净资产或评估值，本层不估）；契税和股权转让以外的印花税（契税只涉及不动产）。不属于优化层的：判断点的回答、事实的来源核实、可读文字与报告、动作词表之外的新结构的发明（词表是数据，谁都可以提行，进表要过校验）、界面。

**用语**（各层规范、产物和报告共用；`brief.json` 的 `terms` 是同一份）：

| 词 | 含义 |
|---|---|
| 结构 | 一个候选：从付款公司到终点的一条持股路径，加上走到这条路径要做的股权转让或迁居；c0 是现状结构 |
| 情景 | 一组判断点答案，对所有结构相同：全有利、只有一个点对客户不利、全不利 |
| 分支 | 一个结构在一个情景下的税 |
| 区间 | 一个分支的 floor 和 ceiling，来自未知事实和累进表；不是不同情景之间的差 |
| 最坏情况 | 全不利情景 |
| 判断点 | `键@地区`：谓词加认定它的地区；about 是问的是谁 |
| 方案 | 报告层的词：选定的结构，加上要做的事、条件、时点和退路；优化层只给结构 |

| 输入 | 内容 |
|---|---|
| 事实 | 与规则层同：款项事实（holding_pct、holding_months、amount、date…）、`payer.*`、`payee.*`，谓词答案（yes / no / unknown + 依据），structure 变量 |
| 终点集合 T | 钱最终可以到谁手里：一个或多个 (法域, 主体)，如"新加坡公司"和"新加坡个人"；缺则 T = {当前收款方}，只做单跳 |
| 求值日、模式 | 支付日；`plan`（新插入的实体的 structure 变量为 PLAN）或 `record` |

| move.csv | 动作词表，见 §4.4 |
| 限制 | 跳数上限（默认 3，即中间地区 ≤ 2）、动作叠加上限（默认 3）、每节点标签数上限 |
| 硬约束 | 可选：排除的法域集合（不建这些节点），或要考虑的法域集合 `consider`（只建这些和现状、终点、已知实体所在的法域）、是否允许重组动作、终点集合之外不许停留的主体类型。只有过滤，没有偏好权重——目标仍是单一的总税 |
| 核算日 | 算暴露额用的日期（§4.7）：从各跳的申报期限（规则层 `reference_params` 里的期限参数）到核算日计利息；缺则 = 求值日，利息为 0 |
| 汇率 | 可选：款项币种对各法域币种的汇率表（`tools/fx.py` 的 fx.json，或调用者手填，每个数带来源和日期）。用于两处：把到达个人终点的金额换成收款方币种（`amount_payee_ccy`），供累进税率表；把一次性成本的输入（净资产、成本、评估值，被转让公司币种）和各地转让税换成款项币种，才能和年股息税相除、相加（§4.7）。缺某币种则前者不传该变量（规则层给档位区间并记 MISSING），后者的一次性成本整项 MISSING 并标 `fx_missing`。税法规定了汇率的地区按规定取：数据库 `<jur>.<slot>.fx_rate_*` 参数记录用哪种价、哪一天、谁的价（内地：扣缴义务发生之日的人民币汇率中间价，收款方按月末 / 上月末；日本：取引日的主要往来银行 TTM；泰国：支付日商业银行卖出价或泰国央行参考平均卖出价，择一后不得变更；新加坡、香港无规定），`fx.py --jur` 读这些参数选日期和源：内地取外汇交易中心中间价（官方数），泰国取央行 API（需 key，否则用市场价并标注），日本没有官方 TTM、以三菱UFJ银行的 TTS / TTB 中值作代表并标注；fx.json 的每个数带 rule_cites |
| 终点个人的事实 | 终点集合里的个人节点要有 `other_taxable_income`（该年其他应税净所得，收款方币种）；缺则同上进未决项 |
| 重组的作价 | 可选：被转让公司最近审计报表的所有者权益（`net_assets`，客户事实，带出处）、持股成本（`cost_base`）和币种（`currency`，缺则按该公司所在地币种）；成本另用一种币种时写 `cost_currency`，按 fx.json 换算并标 `cost_converted`（法定的折算日期另由规则决定）；有评估报告时 `appraised_value` 替代净资产作对价。缺净资产则该候选的一次性成本整项 MISSING，候选仍在，只是一次性成本未知。成本缺失只在某一侧真对转让所得征税时才列为未决项 |
| 过往股息 | `past_payments`：此前每笔股息一行（date、gross、payee_share、withheld、net_received、treaty_claimed、source），见产物 `past_payments.json` |

| CFC 与迁居的事实 | 中间公司或留存公司作为付款方的 `payer_etr`（实际税负）、`specified_cfc`，写在该实体的 facts 里；迁居个人的 `exit_assets_value`、`exit_assets_cost`（迁出地币种）、`years_resident_last_10`。终点集合里的个人节点不在已知实体中、而已知个人住在别处时，按"此人迁居"处理（§4.7） |

## 4. 算法

**名称**：带资源约束的多标签最短路（resource-constrained shortest path, label-setting），即多准则 Dijkstra（Martins 1984；Desrochers–Soumis 1988 的标签算法）。**原理**：按"中间实体把税后净额全部再分配"的约定，留存比例是各跳 (1 − t_k) 的连乘，总税最小等价于 Σ −ln(1 − t_k) 最小，于是边权可加，最短路成立；边权是区间、还带着未决项，所以每个节点不保留一个最优值而保留一个非支配标签集，算法返回的是到终点的帕累托前沿，而不是单条路。

### 4.1 建图

- **节点** = (法域, 主体, 资源状态)。主体 ∈ {company, individual}；资源状态 = 已用跳数、已做的动作（见 §4.4）。个人是节点："个人在新加坡"是一个终点节点。
- **源** = 付款方 (S, company)。**终点集合 T** 来自输入。
- **边** = 一跳股息流 (tail → head)，只在库里六个股息槽位（outbound_wht、inbound、final、residence、cfc、anti_abuse）齐全的法域之间生成（规则层 `coverage`）；penalty、restructure 格缺时边仍建，只是暴露额、一次性成本标 missing；同一对法域、不同动作组合是不同的边。
- **边的事实** hop_facts：tail 作为付款方的事实（它若是上一跳的收款方，取上一跳的 `payee.*`）、head 作为收款方的事实（现状实体取事实；新实体只有动作设的）、款项事实。
- **边权**：规则层 `eval_flow(tail.jur, head.jur, head.subject, date, hop_facts, answers, mode, assume)` 给出该跳的八个输出项，按 §4.5 合成综合税率 t = [t_floor, t_ceiling]，w = −ln(1 − t)，两侧各算。要求 t < 1（库里没有 100% 的税；若出现则该边不可行）。边同时带上 needs（该跳输出项的 needs 之并）和 items_ref。
- **边局部性**：t 只依赖 tail 的事实、head 的事实和款项事实，不依赖更早的跳，这是最短路成立的前提。跨跳的依赖有四种，前两种在候选级重算（候选的 hops/ 用重算后的事实，标签权重可能偏乐观，产物 note 写明）：一是付款方的“所得已纳税 / 税率”可以从上一跳的 inbound、final 输出项推出（`payer_income_taxed`、`payer_tax_rate`，调用者没给时由本层推入）；二是现状收款方在路径上换了持有人（下游节点不是它已知的母公司）时，它上游那跳里关于母公司的安全港事实（parent_*）不再成立，按新持有人替换、待遇是否不劣记 MISSING。后两种：一是内地的多层间接抵免，作为资源维度处理（§4.2），本版不启用。二是进入个人节点的边：个人的 final 格可能是累进税率表（规则层 `schedule`），有效税率取决于到手金额，而到手金额 = 源头金额 × 前面各跳的留存比例。个人是终点、不再往下分，所以这类边不预先定权：graph.json 里标 `amount_dependent`，权重在标签松弛时按该标签现算（§4.3）——`amount_payee_ccy = amount × exp(−w_label) × 汇率`，floor 侧用 w_floor、ceiling 侧用 w_ceiling，连同 `other_taxable_income` 作为 head 的事实传给 `eval_flow`。没有汇率或其他所得时不传，规则层给档位区间并记 MISSING。

### 4.2 标签与支配

一个标签 L = (node, w_floor, w_ceiling, needs, resources, pred_label, edge)。

- `w_floor`、`w_ceiling`：从源到 node 的累计权重，两侧分别累加（§4.5 的单调性保证两侧各算一次即得端点）。
- `needs`：沿途各边 needs 之并（变量名、谓词键）。
- `resources`：已用跳数；已做的 restructure 动作；路径蕴含的转让集合（卖哪家公司的股权：源公司换持有人 = `sell:源`，现状收款方换持有人 = `sell:收款方`，增持 = `acquire:<动作>`）；（可选维）可抵免税额。转让集合进支配条件（⊆），因为卖不同公司的一次性成本不可比，标签阶段还不知道成本。
- **支配**：L1 ≽ L2 当且仅当 w_floor₁ ≤ w_floor₂ 且 w_ceiling₁ ≤ w_ceiling₂ 且 needs₁ ⊆ needs₂ 且 resources₁ 不劣于 resources₂（跳数不多、重组不多）。needs 不同且互不包含的标签不可比，两个都留。
- **资源约束**：跳数 > 上限、动作叠加 > 上限的标签丢弃。

### 4.3 标签算法

```text
labels(graph, source, T, limits):
  init: L0 = (source, 0, 0, ∅, 跳数 0, None, None); open = {L0}; labels[source] = {L0}
  while open ≠ ∅:
    L = open 中 (w_ceiling, w_floor) 字典序最小的标签           # label-setting：按不利侧弹出，弹出的标签不再改变
    for edge in out_edges(L.node):
      if edge 违反资源约束 given L.resources: continue
      if edge.amount_dependent: edge = eval_edge(edge, amount × exp(−L.w_floor) × fx, amount × exp(−L.w_ceiling) × fx)   # §4.1，进入个人终点的边按标签现算，结果记进 hops/
      L' = (edge.head, L.w_floor + edge.w_floor, L.w_ceiling + edge.w_ceiling, L.needs ∪ edge.needs, L.resources + edge, L, edge)
      if 存在 M ∈ labels[edge.head] 且 M ≽ L': continue           # 被支配，丢弃
      删除 labels[edge.head] 中被 L' 支配的标签；labels[edge.head] += L'；open += L'
  frontier = ∪_{n ∈ T} labels[n]
  return labels, frontier
```

边权非负（t ≥ 0 ⇒ w ≥ 0），label-setting 的"弹出即定"性质成立：按 w_ceiling 弹出的标签不会再被更小的 w_ceiling 改进；两侧和 needs 的非支配集保证前沿完整。每节点标签数有上限时按 (w_ceiling, w_floor) 截断并在产物里标 `truncated`。

### 4.4 动作与终点

`move.csv` 列：move_id、kind（path / fact / entity）、sets（`名=值` 或 `名=<arg>`，分号分隔）、arg_domain（`jur` / `pct:25;50;100` / `months:6;12` / `bool` / `company;individual`）、precondition（中缀条件，语法同规则层 §3，对现状事实求值）、restructure（`transfer` / `acquire` / `no`，见 §4.7）、note。最小词表：`via(jur)`（经过新法域 = 插入持股公司，restructure=transfer）、`direct`（去掉中间公司，restructure=transfer）、`holding_pct(pct)`（增持，restructure=acquire）、`wait_months(months)`、`remit(bool)`、`payee_type`。

动作进图的方式：
- `via` / `direct` 不是动作而是路径本身：经过某法域就是走了那条边；现状路径是候选 0，无论是否在前沿都写进产物。
- `fact` 类动作（提持股、推迟支付、不汇入）改一跳的 hop_facts，生成同一对法域上的并行边；每条边记它用了哪些动作；叠加上限是资源约束。
- `entity` 类动作（改收款主体）改 head 节点的主体，即选另一条边。
- 现状路径之外的持股改变都算重组：一条候选路径上每一处与现状不同的持股关系，对应一次股权转让——转让方是现状持有人，被转让公司是它持有的那家。每次转让调规则层 `eval_transfer(被转让公司法域, 转让方法域, 转让方主体)`，得到来源格、居住格的两个输出项，合成一次性成本（§4.7）。迁居（个人改居住地）的成本只记名字。
- `restructure` 作资源维度：已做的转让和增持记在标签里，排序时同总税下"不重组"优先；两类的成本算法不同（§4.7）。

### 4.5 边的综合税率与目标

第 k 跳（边）由规则层的输出项合成：

```text
wht_k     = outbound_wht 项的值（%）；absent 或 None → 0 并标 note
incl_k    = inbound 项的值（计入比例 %）；absent → 0
rate_k    = final 项的值（税率 × 本格计入比例，%）；absent 或 None → 0 并标 note
s_k       = 本跳之前这笔所得已负担的税占其税前额的比例：源头公司自己的所得税（payer_etr，否则 payer_tax_rate）和之前各跳的税，收款地自己征的不算
u_k       = s_k / (1 − s_k)                                               # 每单位股息背后的基础税
base_k    = 100 × (1 + u_k)  若 inbound 带 credit_underlying 且库里 <jur>.inbound.underlying_gross_up 为 yes，否则 100
res_k     = incl_k / 100 × rate_k × base_k / 100
credit_k  = min(res_k, wht_k·[credit] + 100·u_k·[credit_underlying])     # 普通抵免以居民地税为限；credit_underlying 还抵基础税（内地第 24 条、香港 s50AAAB）
t_k       = (wht_k + res_k − credit_k) / 100                              # 本跳综合税率
w_k       = −ln(1 − t_k)
总税 per 100 = 100 × (1 − Π_k (1 − t_k)) = 100 × (1 − exp(−Σ_k w_k))
```

两侧各算一遍：floor 用每格 floor，ceiling 用每格 ceiling。成立的前提是 t_k 对每个分量单调不减（wht、incl、rate 增则 t 增，credit 增则 t 减，而 credit 本身随 wht、res 单调），所以每侧取极值即得区间端点，不必枚举组合。cfc 项为 yes 的跳标 `cfc_flag`（归入税额不在公式里，库里没有归入比例参数）。出现 None 的跳在税额表里标 `value_missing`，该分支标为不完整，排序时排在所有完整的之后。"全额再分配"是候选的定义；客户要留存的，用 `remit(no)` 或把留存地加入终点集合另作候选。

**境内一跳**（付款方与收款方同一地区）：不计预提，计入比例取 100，由 final 格定税。

**CFC 归入**：本跳收款地的 cfc 格归入付款方的利润时，本跳改按归入计税（同期全额分配，之后的股息排除，不重复计）。有抵免时 t_k = max(wht_k, (r − s)/(1 − s))，r 为 cfc 格的归入税率；s 在 `credit_underlying` 时取 s_k，在 `credit` 时只取付款方自己负担的税（上一跳的税，源头公司则是它的所得税）。没有抵免时 t_k = wht_k + r。归入待定时 floor 取不归入、ceiling 取归入。付款方与收款地同属一地时不适用。钱停在终点公司、而它的已知股东所在地的 cfc 格归入时，路径末尾加一个留存伪跳（终点 → 股东，只有 cfc 格，不付款），同样计税。多层受控公司向同一股东逐层归入时可能重复计算，产物如实列出。

**依赖路径的边权**：s_k 取决于路径。建图时只有源头公司那一跳知道 s，其余边按 s = 0 算（上界）并标 `prior_dependent`；标签算法对这类边按标签的累计权重重算（不分谁征的），候选路径逐跳重算时按地区精确扣除收款地自己征的税。

### 4.6 分支（情景枚举）

```text
fork(path, items):
  D = {key : 某跳某项的 pending 里有 ("DISCRETION", key)}     # 已过规则层的反事实筛选；只取股息跳（hops/）的项，restructure、penalty 格的谓词不分支
  取 D 全有利重算，新出现的判断点并入 D，至多三轮             # 一条存疑的否决会盖住它所否决的规则，那条规则的判断点要等否决定了才打开
  if D = ∅: return [branch(path, {})]
  branches = []
  for assignment in {yes, no}^D:                               # |D| 通常 ≤ 3；超出上限取全有利、全不利和每次只有一个不利，并标记；有利方向来自 predicate 的 favourable
    items' = 逐跳 eval_flow(…, answers ∪ assignment, mode, assume ∪ keys(D))
    branches.append(branch(path, assignment, items'))
  return branches
```

判断点按 `谓词键@认定地区` 展开：问这个点的格属于哪个地区，就由哪个地区认定（内地和香港的反避税是 gaar@cn、gaar@hk 两个点）。客户不带地区的答案对所有地区都成立。

分支只对前沿路径和候选 0 做，不进标签状态（否则标签数指数增长）。分支里取定的答案以 `assume` 传入，规则层的输出项会把它们列在 assumptions 里并附去假设后的区间——分支不是把谓词当事实，是把它当标注过的假设。MISSING 和 PLAN 不分支：它们是要问或要定的事实，留在未决项里。

### 4.7 排序、差额、未决项

```text
rank(branches):
  完整的分支按 (floor ↑, 回本次数 ↑（不重组 = 0，未知排后）, ceiling ↑, 推迟付款(no 先，wait_months 动作), 跳数 ↑, branch_id) 排序，确定性     # 字典序；推迟付款的时间成本不在税额里
  支配: A.ceiling ≤ B.floor 且 A.path_complete = B.path_complete → B.dominated_by += A        # 区间支配
  不完整（value_missing 或 path 未到终点）的分支另列，不参与支配

delta(a, b) = {floor: a.floor − b.floor, ceiling: a.ceiling − b.ceiling, amount 同}           # 逐侧减法
deltas: 每个分支相对 候选0 的对应分支、相对本候选的全不利分支（后备）、相对第一名

open_items(ranking):                                                                            # 一次一因子敏感性
  for need in ∪ 每个候选的最优分支的 needs ∪ 被假设遮住的 needs（输出项 without_assumptions.needs，标 hidden_by_assumption）:
    A = 把该项取有利重算排序；B = 取不利重算排序      # 变量的取值：bool 取 true / false；数值取规则里与它比较的每个门槛及其两侧；enum 取允许值；受影响的分支逐跳重跑，取 ceiling 最低 / 最高的结果
    changes_rank = A 与 B 的第一名不同
    narrows_best = 第一名的区间在 A 或 B 下变窄
  按 (changes_rank, narrows_best, 出现次数) 降序；附变量的 question / 谓词的 question 与 factor_vars 当前值（来自规则层 judgment_points）
  判断点按 (谓词键, 问的是哪个收款人) 分开列（同一个 bo 在港公司和新加坡公司是两个问题），if_yes / if_no 在该收款人的全部完整分支里取各自最好的
  本层推出的事实（§4.1 的 payer_income_taxed、payer_tax_rate；持股链推出的 owner_safe_harbour（9 号公告第四条第（四）项）和 passes_on_within_12m（结构本身把股息付到第三地）；转让里的 future_cn_tax_not_reduced）另列 kind = derived：值、推导依据、读它的规则、要向谁确认；bool 的取反面重算一次，看第一名变不变
  转让格的未决项（PLAN 的 consideration_in_shares、DISCRETION 的合理商业目的、MISSING 的集团关系比例等）列 kind = one_off，各取值重算一次性成本；它们只通过回本次数给税相同的结构排先后，changes_rank 为否
```

不把区间压成期望值。排序用有利侧：判断点取有利答案、待定事实取有利一侧，这是客户条件带来的筹划空间；有利侧依赖的事实和判断点列为该结构的前提（brief 的 relies_on 与 judgment_points），不利侧并列展示，只作风险提示，不参加比较。代价不算，顺序只表达分辨力。2026-11-02 用户定。

**情景**（`scenarios.json`）：所有结构在同一组答案下比较：全有利、每次只有一个点对客户不利（点取全部结构的并集）、全不利；不带某个点的结构在该情景下沿用全有利的值。每个情景按上面的排序键给出第一名和第二名。结构名次（`structure_rank`）= 全有利情景下的顺序；分支名次只是 ranking.json 的行号。ranking.json 先按分支里对客户不利的答案个数（`answers_against`）排，再按排序键，所以第 1 名就是全有利情景的第一名；某个不利答案碰巧更便宜的分支不会排到前面，它只在对应的情景行里出现。判断点的 `changes_rank` 改为：该点不利的情景和全有利情景的第一名是否不同；附两种情况下的第一名（金额、是否重组、一次性成本、回本次数）和 `value_at_stake`（全有利第一名在该点不利时多交的税）。一次性成本类未决项（净资产、成本、离境税的输入）只要它的结构在某个情景下排第一，就算会改变结论。这仍是单一目标：情景表只说"这组答案成立时谁最便宜"，不估概率。

**一次性成本**（one_off_cost）：按候选算一次，候选的每个分支共用（分支只改股息跳的假设）。候选上每处持股变化 k 分两类——`transfer`：集团内转让（插入或去掉中间持股公司，转让方是现状持有人）；`acquire`：从第三方增持（`holding_pct(pct)` 一类动作），卖方的税不是客户的成本，只有买方一侧的印花税。所有金额按 fx.json 换成款项币种：

```text
consideration_k = appraised_value（有评估）否则 net_assets × 变动的持股比例 / 100（输入；缺则整项 MISSING，标 valuation_missing；open_items 里每个缺数的被转让公司一条，about 写该公司）
gain_k          = consideration_k − cost_base（cost_base 缺则 = consideration，即税基上限，并标 cost_missing）；acquire 类 gain_k = 0
income_tax_k    = gain_k × (source.rate + home.rate − credit_k) / 100   # transfer 类：eval_transfer 的两个 restructure 格，两侧各算；居住格有 credit 效果（内地第 23 条、日本第 69 条）时 credit_k = min(source.rate, home.rate)，否则 0 并标 no_credit
stamp_k         = consideration_k × stamp / 100                    # transfer 类：来源格的 stamp（双方合计）；acquire 类：只取买方一侧的 stamp 规则（规则 id 以 transferee / bought_note 结尾；卖方 transferor / sold_note；分不出则全额并标 stamp_side_unknown）
one_off_cost    = Σ_k (income_tax_k + stamp_k)，floor / ceiling 各算；restructure 格的 DISCRETION（如合理商业目的）不展开分支，以区间带出并进 open_items（kind = one_off）
间接转让：被转让公司持有另一地公司时，再对底层公司算一笔 `indirect`（目标 = 底层公司，`indirect_transfer = true`，集团关系比例从已知实体的持股链算，算不出记 MISSING）；只有所得税、没有印花税（底层没有书据）；并在 `costs_unquantified` 列"间接转让申报"
7 号公告第六条第（二）项（再次间接转让时中国税负不减少）由本层推出：分别按新持有人和旧持有人直接转让该中国公司求 cn 的 restructure 格 ceiling，新 ≥ 旧 则 `future_cn_tax_not_reduced = true`；推导记进 transfers 的 derived 并列 open_items（kind = derived，about = 被转让的中国公司）；任一侧求不出则该变量留空进 PLAN
转让方是个人时，其居住地 restructure 格可能是累进表（泰国居民）：本层把转让所得按汇率换成居住地币种填 `amount_payee_ccy`，`other_taxable_income` 取该实体的事实；缺汇率则表的两端作区间
baseline        = 同一组答案下（该分支没有的判断点取有利答案）：现状到达终点时取现状，否则取到达终点、不重组的最便宜结构
saving          = tax(baseline) − tax(候选的分支)，两侧各算     # 每次付款省的税，按 amount 算，假设每次金额相同（写进产物 note）
payback_payments = one_off.floor / saving.floor（有利侧：一次性成本取 floor，即自由裁量取有利答案；税取 floor）；一次性成本为 0 → 0；saving.floor ≤ 0 → 无（不回本）。不折现
```

排序：主键是每次付款的税（floor），税相同时按回本次数（短的先，不重组为 0，一次性成本未知的排后），回本上限 X 作过滤。回本另算一份相对“最好的不重组完整分支”（同样假设下）的 `vs_best_no_restructure`。候选的 restructure 标记由它蕴含的转让决定（transfer / acquire / holder_unknown），不由动作表决定。一次性成本的输入（净资产、成本、评估值、汇率）都带来源或假设标记，进产物；net_assets、cost_base 缺失作为 open_items（kind = one_off）列出。一次性成本只算直接触发、当时就要缴的税；restructure 格的 DISCRETION（如合理商业目的被否后的间接转让税）在 floor 取有利答案，ceiling 带出被否时的数，进 open_items（kind = one_off），报告把它写成假设，不写成成本区间。

**离境税**：终点集合里的个人节点不在已知个人的居住地时，视为此人迁居：restructure 记 `relocate`，此人持有的股权不算转让；一次性成本加迁出地 exit 格（`<jur>|individual|exit|*`）的税：(exit_assets_value − exit_assets_cost) × 税率，按迁出地币种换算成款项币种。输入缺失标 `exit_inputs_missing`；迁出地没有 exit 规则时按缺项记录取 0；已知个人不止一个时标 `exit_person_unknown`。

**暴露额**（exposure_if_denied）：一条分支里以 yes 假设取得的待遇（协定上限、免税、抵免）若事后被否，要补多少。对每个这样的分支 b 和它的全不利分支 b⁻：

```text
tax      = tax(b⁻) − tax(b)                                   # 补税差额，两侧各算
按格拆分：每跳里带假设的格——来源地（outbound_wht、anti_abuse）分到 到达该跳的金额 × Δwht，居民地（inbound、final、anti_abuse）分到 到达该跳的金额 × Δ(res − credit)；到达金额按 b⁻ 的留存比例算
每个格：penalty 格 = 该格法域的 <jur>|all|penalty|*（规则层 eval_cell）；来源地格从申报期限计利息，居民地格没有期限参数时标 deadline_missing
interest = tax_cell × Σ_i pct_i × periods_i(期限 → 核算日) / 100，再按 interest_cap 封顶；period = once 的只加一次
fine     = tax_cell × [fine_min, fine_max] / 100
offset   = tax − Σ_格 tax_cell                              # b⁻ 里不带假设的格反向变动（如下游外国税抵免变大），不计利息罚款，非零时标 offset_elsewhere
total    = tax + Σ_格 (interest + fine) = Σ_格 (tax_cell + interest + fine) + offset，floor / ceiling 各算；产物里逐格列出
```

期限来自该跳 `reference_params` 里的 `withholding_deadline_*` 参数（缺则利息项标 `deadline_missing`，只给罚款）；penalty 格的事实是 `overdue_months`（= 期限到核算日的月数，由本层算好传入）和方案自己的行为（`PLAN_CONDUCT`）：按规定申报了待遇（claim_reported = true）、没有隐匿（concealment = false）、没有过失（negligence = false）、提交了申报（return_filed = true）——方案的执行步骤本来就要求如实申报（内地按 35 号公告第十六条只追税款和滞纳金，D-cn-9）。剩下的情形变量（voluntary_payment）不传，让规则层以区间回答：exposure 的 floor 用格的 floor，ceiling 用格的 ceiling。penalty 格缺（absent）则整项标 `penalty_missing`；格在但没有 interest 项（如日本尚未登记下一年的特例税率）则利息项标 `interest_missing`，罚款照算。剩下的情形变量进 open_items，kind 为 `exposure`：它们不改变排名（changes_rank 恒为 false），只收窄暴露额，排在税额类未决项之后。偷税、隐匿等更重的情形需要方案不会制造的事实，产物只列名字。这是区间，不是概率：它回答“错了要补多少”，不回答“会不会错”。

### 4.8 穷举基线

`check.py` 对同一张图做深度优先的完全枚举（跳数 ≤ 上限），对每条路径按 §4.5 算总税区间，取非支配集，与 labels.json 的前沿比对：前沿必须等于枚举的非支配集（标签截断时允许前沿 ⊆ 枚举集并标记）。当前规模（法域 11、跳数 ≤ 3、动作叠加 ≤ 3）下枚举是 10³–10⁴ 条路径、秒级，所以基线永远可跑；标签算法的价值在规模长大时仍然精确，而不是在今天更快。

### 4.9 规模

节点 ≤ 11 × 2 × 资源状态数；边 = 法域对 × 动作组合；每边一次 `eval_flow`（毫秒级）；标签数受非支配集和上限约束；分支 ≤ 2³ × 前沿路径数。整轮秒级到分钟级，可全量重跑。

### 4.10 指定路径、执行要件、两轮差异

三个按需的只读功能，都不改搜索，只是对已有函数的调用加落盘：

- **指定路径**（`evaluate --path <node;node;…> [--moves …]`）：调用者给一条路径（可以不在前沿，可以是客户自己的想法），本层按 §4.1 的方式建它的边、按 §4.5 算税、按 §4.6 分支、按 §4.7 算差额、暴露额、一次性成本，产物格式与前沿候选完全相同，cand_id 以 `x-` 开头并写进 paths.json（标 `requested`），参与 deltas 但不改变 ranking 的名次（排名只对前沿和候选 0）；路径用到的法域没有六格齐全则报错不猜。
- **执行要件**（`requirements`）：对每条候选（含 `x-` 路径）每跳，取该跳输出项里取用的有利效果（cap、exempt、share、credit、协定口径），调规则层 `requirements(slot_key, effect)` 得条件树（变量、参数、谓词、procedure 原句）和 `reference_params`（期限、证明年度、门槛），原样落 `requirements/<cand_id>.json`，每项带 cite_ids。不排步骤、不算日期；报告的行动清单从这里取，和税额同版本。
- **两轮差异**（`diff --against <另一产物目录>`）：对两轮产物按 cand_id / branch_id 对齐，列出：排名变化（谁上谁下、新出现、消失）、每个分支两侧区间的变化、未决项的新增 / 消失 / 分辨力变化、一次性成本与暴露额的变化、version.json 里哪些输入项的哈希变了，以及 `engine_changed`（optimize.py、rule.csv、param.csv、doc.csv 各自是否变了；version.json 记 `engine_sha256`），使输入不变时的换位有来由。只列差异，不解释原因。两轮 move.csv 或规则层版本不同时标 `incomparable` 并仍输出。

## 5. 产物

全部 JSON，UTF-8，键名英文。每个文件头部带 `version`（与 version.json 相同的哈希），不同轮的产物不混用。

- `graph.json`、`labels.json`、`paths.json`：§2 结构；hop_facts 原样保存（含调用者给的出处字段，优化层不改）。
- `hops/<cand_id>.json`：规则层输出项原样（每跳八项）；分支重算的项放 `hops/<branch_id>.json`。
- `transfers/<cand_id>.json`：每次持股变化的 `eval_transfer` 输出项原样；`penalty/<jur>.json`：用到的 penalty 格输出项原样。deltas 里的 `items_ref` 指向这两处。
- `tax.json`：§4.5 的每跳分量与总计，两侧；每跳另带 prior、prior_own（本跳之前已负担的税）、underlying、cfc_inclusion，留存伪跳标 retention；每个分量标它来自哪个输出项（`hop, slot_key`）。
- `brief.json`：读者先看的短版：用语（terms）、第一名、现状、在某个情景下排第一或第二的结构（全有利和全不利两种情况的税、一次性成本、每次省的税、回本次数、在哪些情景排第一）、情景表（只列会换掉第一名或改变金额的情景，其余计数）、推荐结构和现状自己的判断点（两种答案下的第一名和得失）、会改变结论的缺口、其余结构的数量。不含新数字，全部取自其他产物。
- `scenarios.json`：§4.7 的情景表全量。
- `past_payments.json`：有 `past_payments` 输入时才有。每笔按当时日期重算现状这一跳：法定税额、协定税率、可退金额（前提是当年判断都有利）、退税期限（`<jur>.outbound_wht.refund_claim_years`），以及税额、净额对不上的说明。
- `ranking.json`、`deltas.json`、`open_items.json`：§4.7；ranking 每行另带 `answers_assumed` 和 `range_all_branches`（该候选所有判断结果下的最宽区间）和 `structure_rank`；deltas 里的 `exposure_if_denied` 每个分量标它来自哪个 penalty 格和哪条规则。
- `gap.json`：规则层 `gap` 对每条边的结果，以及因库不全被排除的地区。
- `requirements/<cand_id>.json`、`diff.json`：§4.10。
- `version.json`：输入哈希——事实、终点集合、move.csv、限制、硬约束、汇率表（fx.json）、核算日、作价输入、回本上限，逐项哈希再合成总哈希，缺省的项哈希空串——`rule.version()`、生成时间、限制参数。任一项变了总哈希就变，"同输入同产物"按总哈希判。

产物不含任何文字性结论。一次性成本里能算的（转让所得税、印花税）有数、有出处；算不了的只有名字（`costs_unquantified: ["indirect transfer reporting"]`），没有数。

| 函数 | 输入 → 输出 |
|---|---|
| `run` | 事实文件、终点集合、日期、模式、假设、限制 → 整个产物目录 |
| `graph` | 同上（不搜索）→ graph.json |

| `paths` | labels.json + 现状 → paths.json、hops/ |

| `transfers` | 一个候选 + 现状 + 作价输入 + fx.json → transfers/<cand_id>.json（每次持股变化一组 `rule.eval_transfer` 输出项） |

## 7. 校验

`optimization/tools/check.py` 对一个产物目录报错的情形：

1. 候选 0 缺失；路径用到的动作不在 move.csv；precondition 不成立的边出现在图里；边重复；
2. 任一跳的输出项与现场重跑 `rule.eval_flow` 不一致（数值、rules_applied、pending、assumptions）；transfers/ 与现场重跑 `rule.eval_transfer`、penalty/ 与现场重跑 `rule.eval_cell` 不一致；
3. 边权不等于按 §4.5 从输出项重算的值（`amount_dependent`、`prior_dependent` 的边按所属标签重算，穷举基线也一样）；标签的累计权重不等于沿 pred_label 回溯的边权之和；floor > ceiling；hops 里的 `amount_payee_ccy` 不等于 amount × exp(−w) × fx.json 里的汇率；
4. 前沿与 §4.8 穷举基线的非支配集不一致（截断除外）；标签集里存在被支配的标签；
5. tax.json 不等于按 §4.5 从输出项和每跳记录的 prior 重算的值；排序不符合 §4.7 的键；deltas 不等于按 tax.json 重算的差；不完整的分支参与了支配；
6. 分支的答案没有作为 assumptions 出现在对应输出项里（把假设当事实）；
7. 产物里出现了不在输出项或 move.csv 里的数字；version 哈希与输入不符；
8. 暴露额不等于按 §4.7 从 tax.json 和 penalty 格重算的值；利息超过 interest_cap；罚款不在 [fine_min, fine_max]；一次性成本不等于按 §4.7 从 restructure 格和输入重算的值；给了 N 时排序键不是 total_N；

9. requirements/ 里任一条件树与现场重跑规则层 `requirements` 不一致；`x-` 路径参与了 ranking 的名次；diff.json 里的任一差异在两轮产物里对不上；
10. `optimization_test.csv` 任一条不过：`test_id, facts, destinations, date, answers, expect`，expect 为 `<branch 描述> <floor> <ceiling> <rank>` 或 `open <键,键>`。

**不变量**：同输入同产物（哈希相等）；每个数可回到输出项，再由 `rule/tools/trace.py` 回到条文；候选 0 永远存在；边权非负。

## 8. 构建与交付

- `python optimization/tools/optimize.py run --facts <facts.json> --destinations '<jur>:<subject>;…' --date YYYY-MM-DD [--mode plan] [--assume …] [--max-hops 3] [--max-moves 3] [--max-labels N] [--exclude jur,jur] [--no-restructure] [--fx fx.json] [--as-of YYYY-MM-DD] [--valuation <valuation.json>] [--payback-max X] --out products/<case>/`（§3 的每项输入各有一个开关；`--valuation` 是净资产、成本、评估值的文件）
