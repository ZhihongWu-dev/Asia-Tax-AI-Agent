# 云端知识与聊天研究链路

日期：2026-09-27。本轮完成范围是香港 FSIE 的受控研究链路，不是完整 PRD、L1 或客户税务结论验收。

## 可用流程

1. 用户输入问题，DeepSeek 提取新增事实。无新增事实的咨询转入官方资料检索，不使已确认事实失效。
2. 检索支持四个裁定编号（68、72、74、75）、法条编号和有限税务主题的中英文关键词。没有命中明确显示空结果，连接失败返回可重试错误，失败消息不落库。
3. 有案情时沿用逐项追问和显式事实确认。分析运行现有五个业务规则节点与人工门槛，绑定各节点的原文引用。
4. 金融实体排除、境外纳税与转换、反混合、主要目的、申报与证据保存五项生成明确的人工复核任务、缺失字段和条文导航，仍未自动判定。
5. 股息分析附两个按关键词匹配的官方裁定参考，每个保留全部七节。案例相关性不等于适用性，案例裁定不转化成用户案件的结论。
6. 结果、原文和来源元数据冻结到会话 JSON；后续入库不改写已保存引用。修改事实后旧分析标记过期。

## 云端配置与数据

- `FSIE_DATABASE_URL` 指向 Supabase Session pooler PostgreSQL；标准 `postgresql://` 自动转为 psycopg 驱动。会话默认用同一连接，应用不默认创建本地数据库。
- 原有 10 个范围内官方来源已导入，共 697 个片段；四个裁定共 28 节。2023 处置收益修订来源仍按清单排除。
- 8 个 HTML 来源相较原清单哈希有变化，未更新原清单掩盖差异；前端显示待核对。抓取时间不代表法律生效日期，原清单覆盖截止不因本次下载而前移。
- 数据库迁移 `0004_cloud_chat_rls` 接管已有会话表，并对应用表启用无客户端政策的 RLS。服务端使用受信任的数据库账号；浏览器不接收连接凭据。这不替代登录、组织权限或生产账号最小权限设计。
- 法律和案例查询从云端读取。原始下载文件仍在忽略 Git 的本机 raw 目录；云端原件归档、备份恢复演练仍待实施。原文片段及其来源哈希已在云端。
- 旧版 SQLite 会话不自动迁移。随机浏览器 cookie 不是团队账号；不同浏览器的私人案件互相隔离。

## 检索方法与边界

按条文或裁定编号精确查找；一般关键词先在 PostgreSQL 做绑定参数候选检索（最多 120 个），再按命中和片段长度排序，限制每个来源最多两个片段，返回最多七条。中文使用固定主题词映射，不声称覆盖任意中文语义。

未接入 embedding、向量索引、重排模型或自由生成税务答案。一般咨询返回原文引用；分析使用确定性规则及复核清单。官方裁定原文不会送入外部模型。现有来源目录过滤阻止未登记来源被直接引入引用。

## 验证与复现

本次实际结果：100 项离线测试通过；7 项浏览器测试通过；真实 DeepSeek 提取 13 个候选字段，确认后云端保存 21 个法条片段、两个参考案例的 14 节及五项复核任务。四个裁定编号各命中七节，无关天气查询返回空结果。云端记录重读一致、RLS 开启、修改事实后旧分析失效。验证用合成案件已清理。

- 离线：`python -m pytest -q -m "not integration"`，含 10 个合成候选案例规则回归、两种裁定 HTML 结构、编号/关键词/空结果、故障不写入、引用快照、确认保护和 API 边界。
- 浏览器：`apps/web` 下运行 Playwright；测试服务器使用独立临时数据库和明确的模型/知识测试替身，覆盖中英文、刷新、事实确认、来源变化提示、检索空结果和移动布局。
- 真实云端：先启动 `scripts/run_chat.py`，再执行 `python scripts/verify_cloud_chat.py`。使用独立 cookie 工作空间、合成案情和真实 DeepSeek/云端检索，检查持久化、引用、RLS 和事实变更失效；只删除该脚本自己创建的测试案件。结果写入忽略 Git 的 `reports/cloud-chat-verification.json`，不含凭据或案情。
- 旧的 11 项数据库集成测试未对共用云库运行，避免其中的测试初始化影响数据。

## 与 PRD 尚有的差距

完整的十节点自动规则及动态证据访谈、向量混合检索及召回评测、专家验证和金标案例、顾问批准与报告归档、账号/组织权限、云端原件存储与恢复、法规变化影响冻结、公网部署仍是后续独立工作。不得把本轮工程通过当作专业正确性认证。

## 实现依据

开发前核对了 [pgvector 官方仓库](https://github.com/pgvector/pgvector)的 PostgreSQL License、版本和开放问题；其混合检索示例说明词法与向量可以共用 PostgreSQL。本轮不新增向量依赖，先验证词法和编号检索。沿用 [SQLAlchemy](https://github.com/sqlalchemy/sqlalchemy)（MIT）绑定参数和现有 ORM；未复制外部实现。Supabase 连接方式遵循其[官方连接说明](https://supabase.com/docs/guides/database/connecting-to-postgres)。
