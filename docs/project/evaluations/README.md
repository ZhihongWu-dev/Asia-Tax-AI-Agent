## 先看这份

[2026-10-03 简版复测记录](Taxora_复测记录_20261003.xlsx)：一张表，五列，保留20个问题的实际回复和修改建议。长回复用续行保留全文。

旧版[简版测试记录](Taxora_测试记录.xlsx)和[完整测试报告](Taxora_Agent测试报告.xlsx)是2026-09-29的基线，保留用于对照，不代表当前结果。

## 这次做了什么

- 资料咨询先检索云端官方片段，再交给DeepSeek整理直接答案。每段必须提供已检索的片段ID和逐字引文；出处链接由程序生成。未命中资料或引用校验失败会明确提示，不用无依据的回答补位。
- 支持多个法条、案例与法条混合查询、中文括号及去重。按各编号轮流取结果，避免第一条占满名额；自然语言增加有限主题定位，短指引片段按同来源、同快照补充相邻原文。
- 模型不能凭空补法条编号改变检索模式，也不能给外地区问题擅自增加香港连接点。闲聊、案情汇总、规则咨询分别处理。
- 结构化输出最多尝试两次；重试会清空上一轮残留文字。DeepSeek结构化提取和整理关闭额外思考，减少输出预算被占用。取消后不保存半截消息或事实。
- 修复空事实被误标为访谈而报错的问题；收款日期不能自动填成累算日期。修正反混合条文导航，并在抵免检索中避免把豁免门槛当成抵免条件。

**公开资料授权**：2026-10-03用户明确允许将来源清单中的公开香港官方法规、指引、裁定片段发送给已配置的DeepSeek。只从登记的官方URL选取片段；真实客户资料和密钥不在这次授权范围内。合成案情测试规则不变。这一授权更新了早期文档“不向外部模型发送官方原文”的对应限制。

| 原20个对话问题 | 最终20/20返回结果，无引用校验失败兜底 | 旧版17题返回、3题报错；完成不等于税务正确 |

| 离线自动测试 | 140通过 | 含引用、权限、取消、重试、日期区分及实际SQL筛选；11项数据库集成测试未在共用云库运行 |
| 浏览器回归 | 19通过 | 测试模型/知识替身，真实页面与API；含登录界面、发送、停止、历史、确认和手机布局 |
| 前端生产构建 | 通过 | TypeScript与Vite构建正常 |

对话使用真实DeepSeek和已配置的云端知识库，合成事实及临时隔离会话存储，没有写入用户个人聊天。先完整运行20题，再定向复测T04、T11及T12—T15；最终表采用对应最新实际结果。完整案例流程使用再次运行的T12—T15，不代表真实账号HTTP链路或云端会话持久化重新验收。

最终20题平均耗时7.27秒，最长18.90秒；旧基线平均5.84秒。现在多了检索后的答案整理，不能声称整体速度已经提高。检索单轮平均约0.87秒，网络波动明显，不能当作稳定性能指标；尚未并发压测。

## 还没做完的产品能力

1. **专家校准**：逐条核对解释、引用是否真正支持结论、豁免与抵免边界，并提供标准答案。程序目前只检查来源ID和引文存在，不判断整段法律推理成立。
2. **独立召回评测**：目前20题是开发回归集，包含专门修复的主题；还需专家标注的新问题和相关片段，用未参与调参的问题评估召回。
3. **回答与性能**：部分回答仍偏长，时效问题还会夹带历史信息。继续减少无关段落，测首字/总耗时、并发、缓存失效；不要只追求低延迟而省掉依据核对。
4. **完整规则与新资料**：金融实体排除、境外纳税与转换、反混合、主要目的、申报与证据保存五项仍是人工复核任务。本轮没有补成自动税务结论，也没有扩展到新地区、实时法规更新或新增MCP能力。

当前仍是研究助手，不能把这次工程通过说成香港FSIE全部完成、专家验收通过或可以直接执行的减税方案。

## 队友怎样复测

先按根目录README安装依赖，将`.env.example`复制为`.env`，按照[认证说明](../TAXORA_AUTH.md)配置。凭据私下提供，真实`.env`不进Git。

```powershell
# 只读云端检索，不调用模型
.venv/Scripts/python.exe scripts/evaluate_retrieval.py --output reports/retrieval-check.json
# 真实模型调用会产生API用量；固定合成问题，隔离会话，不写云端客户记录
.venv/Scripts/python.exe scripts/evaluate_chat.py --output reports/chat-check.json
# 定向复测：连续追问应包含前置轮次
.venv/Scripts/python.exe scripts/evaluate_chat.py --only T12,T13,T14,T15 --output reports/intake-check.json
.venv/Scripts/python.exe -m pytest -q -m "not integration"
```

问题集在`tests/chat/retrieval_cases.json`和`tests/chat/conversation_cases.json`。本机原始记录在忽略Git的`reports/chat-final-2026-10-03.json`及`reports/retrieval-natural-*.json`；Excel供团队查看实际答案。编号范围和省略式如`15K至15M`、`15K(2)及(3)`尚未展开，过多编号仍受返回上限约束。

实现参考沿用[SQLAlchemy](https://github.com/sqlalchemy/sqlalchemy)的绑定参数查询方式，并借鉴[Haystack相邻句窗检索](https://github.com/deepset-ai/haystack/blob/main/haystack/components/retrievers/sentence_window_retriever.py)的上下文思路；没有复制其代码或新增检索框架依赖。DeepSeek请求选项依据[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。
