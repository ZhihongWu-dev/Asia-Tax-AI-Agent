## 定位

四层里唯一的写作者。数据库、规则层、优化层是铲子，只给结构化的法条、求值、路径和产物；Agent 读这些，自己判断、追问、写报告。Agent 不进任何一层的规范，也不被它们约束；三层对它的唯一要求是输入合法。

## 入口：客户背景 → 事实

- 客户只陈述交易背景并上传单据（见 case_end2end/prompt.md），不提问。
- Agent 把背景和单据抽成规则层的事实：字段字典 = 规则层 `variables()`（client_fact 变量）+ 款项事实（amount、date、holding_pct、holding_months）+ payer.* / payee.*。
- 每个事实带出处（哪份单据、哪一页、原句）和置信；数字从原文解析，不从摘要里猜。缺的不补，留给规则层报 MISSING。
- LLM 抽取只在这里用，不进数据库：一个案子一份材料、量小、客户能核对、Agent 能追问。
- 可用的旧经验（已归档 archive/old-model-2026-10-31/tax_graph）：按变量名定位段落、逐段读、程序校验冲突（单据之间数字不一致时列出而不是选一个）、回复缓存。

## 中段：问铲子

- 规则层：`eval_flow` 看现状；`judgment_points` 看哪些谓词卡住、因素变量当前值；`requirements` / `options` 看要争取某个待遇还差什么；`what_if` 看改一个事实的影响；`trace` 把每个数回溯到条款；`reference_params` 拿期限、证明年度。
- 优化层：graph / paths / ranking / deltas / open_items / exposure_if_denied，全是 JSON，没有结论。
- 谓词（bo、ppt、gaar、substance…）由 Agent 结合上下文回答，答案以 `assume` 传入，输出项会把它列为假设并附去掉假设后的区间。Agent 写报告时必须把假设写成假设。

## 出口：报告

- 解释为什么这条路径排第一：用 deltas 的两侧差额、ranking 的支配关系，不用期望值。
- 每个数字、每个结论带引文到条款（cite_id → clause 原句）；没有出处的数不写。
- 风险评价用两样写：open_items 的分辨力排序（哪个未决项会翻转排名）+ exposure_if_denied 的区间（补税 + 滞纳金 + 罚款）。不打分、不估概率。
- 程序步骤从 procedure 条款和 reference_params 来（期限、表格、证明年度），Agent 排序成动作清单。
- 一次性成本只有名字（股权转让所得税、印花税、间接转让申报），Agent 说明有这项成本，不编数。

## 框架

- 2026-11-01 定为 Claude Code 当 CLI（Codex 集成已删），编排用 LangGraph，不用 LangChain 的 Agent 层，见 `编排CLI规范.md`；要的是每个事实带来源、每个数带引文，不是框架本身。
- 可以双 Agent：一个写、一个只核对出处和算术（重跑 trace、重算差额）。
- 模型：.env 里的 deepseek-flash 做过叙事实验（推理模型，max_tokens 要大），效果可接受。

## 不做

- 改任何产物或库表；补值；替客户核实事实真伪（只能标出单据之间的矛盾）；把判断写成事实。

## 补充（2026-10-31 晚）

**配置思路**：分析 Agent = 优化层产物 + 一堆 MCP 和访问权限 + 轻量 prompt。能力全部开放（规则层查询、数据库条文查询、汇率、联网搜索、读 PDF / 图片、CLI 自带的一切），不约束过程，只约束交付物。GPT-6 那次的教训：约束落在过程上，结果更差。

**prompt 只守的几条（都是对报告内容的要求）**
1. 数字的来源：每个数来自产物或规则层工具的输出，或标明是 Agent 自己的估算；LLM 不自己做税额算术。
2. 假设与事实分开：Agent 替客户答的判断点写成假设并说明依据；客户确认后才改口。
3. 未决项不略过：open_items 里标"会翻转排名"的必须出现在报告里。
4. 来源分层标注：库里的参数和条文（已验收、可回溯）／官方网站原文（可引、未入库）／二手来源（事务所简报、新闻、论坛：只作线索，不作依据）。联网引用带 URL 和日期，复核 Agent 可重查。
5. 核实的边界：能做交叉核对（单据之间、单据与公开注册信息之间的矛盾），不能证明真实性；报告写清。

**产物与报告两条线**：产物确定性、可复现，联网结果不进产物；报告可以用联网结果。

**客户确认了某个点之后**：确认的答案进 facts / answers（带依据），不再是假设；重跑整套产物（秒级到分钟级），新旧版本各自保留；Agent 拿新产物复核结论。open_items 里预先算过"这个点取有利 / 不利时第一名变不变"，所以 Agent 在客户回答前就能说"这个问题会改变结论"。两轮产物目录之间的 diff、指定路径的评价（evaluate）、每条路径的执行要件（requirements）已写进优化层规范 §4.10 / §6。

**正向闭环**：Agent 在网上发现库里缺的或过时的条文，不替库改数，提一条"待采集"给采集方；库仍只收官方原文、过验收。

**第二个 Agent**：只核对，不写内容——拿同样的产物和工具，查报告里的数字出处、假设标注、来源层级、未决项是否齐全。
