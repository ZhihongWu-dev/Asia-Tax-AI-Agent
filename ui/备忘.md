# UI 层备忘

2026-10-31。只记设计要点，不是规范；最后做。

## 定位

没有逻辑。只画优化层的 JSON 产物和 Agent 的报告，所有数字都从产物里读，自己不算。旧模型的 web/（已归档）不复用。

## 页面

**输入页**
- 一个背景陈述框 + 单据上传（PDF / 图片）。只收陈述，不引导提问（见 case_end2end/prompt.md）。
- 提交后显示抽取出的事实表：字段、值、出处（单据 + 页）、置信；客户可改、可确认。

**结果页**
- 路径比较：ranking.json 的顺序，每条路径一行：经过的节点、两侧总税（floor / ceiling）、是否重组、被谁支配；候选 0（现状）永远在列。
- 每条路径展开：每跳的税额分量（wht、计入、居民地税、抵免）两侧，点任一数跳到规则层输出项和条款原文。
- 差额：deltas.json，相对现状、相对后备、相对第一名，逐侧。
- 未决项：open_items.json，按分辨力排序；标出"会翻转排名"和"会收窄第一名"的；每项附问法和因素变量当前值；可在页面上作答后重跑。
- 合规状态：每跳的 requirements（要满足的条件、要答的谓词、要交的文档）、期限、暴露额 exposure_if_denied 区间。
- 引文：所有 cite_id 可点，弹出条款原文和文件来源。

**导出**
- Agent 报告 PDF / DOCX；产物 JSON 原样下载。

## 技术

- 薄：静态页 + 读 products/<case>/ 的 JSON；语言英文为主，一个中文开关。
- 不在这里做任何求值、排序、假设；页面上的作答只是写回输入再调优化层。
