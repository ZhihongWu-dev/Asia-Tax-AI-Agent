# 规则层规范（最小集）

2026-10-31（第三版，取代 2026-10-29 版：功能定位改为为 AI agent 提供逻辑、计算上的辅助，表、语法、求值语义、构建不变）。规则层在 `rule/`。它读数据库（`database/`，见 `database/数据库规范.md`）产出的 jurisdiction、doc、clause、param、treaty、decision，自己维护 rule、variable、predicate、decision、rule_test 五张表，并以此提供一组只读的查询与计算函数（第 5 节）。数据库不依赖规则层；规则层不依赖任何调用者。参考实现在 `rule/tools/`；旧引擎（`tax_graph/`、`official/`）不使用，也不迁移。

**语言**：本规范用中文，供人阅读；英文副本 `rule/rule_layer_spec.en.md`，两者不一致时以中文版为准，改中文版时同步改英文副本。AI 写进文件的一切自写文字用英文——代码、注释、工具说明、prompt（系统实际递交的是英文副本里的那段）、底稿、核对单、handoff、bug 反馈、日志、产物字段；原件、条文、引文、客户原话保持原文，不翻译。唯一例外是给客户看的文字（对客户的回话、briefing）跟客户的语言。核对单的总判断用英文记号：交接包 `RUNNABLE` / `REVISE`，报告 `DELIVERABLE` / `REVISE`（服务也接受原来的中文记号）。

## 0. 功能定位与范围

规则层为 AI agent 提供逻辑、计算上的程序化辅助，帮忙缓解幻觉和上下文限制：把库里的法律变成可查、可算、可回溯的数据和函数。它只提供铲子，不做判断，也不规定怎么用。它保证的只有一件事：**同样的输入永远得到同样的输出，且每个输出都能回到条文和引文**。

| # | 功能 | 用处 | 落实 |
|---|---|---|---|
| 1 | 法律的结构化供给：规则、变量、判断点、口径作为数据，条文、参数、引文随查 | 不用把整部法装进上下文，数字不靠记忆 | §2、§5 |
| 2 | 定位：给定地区、主体、槽位、流向、日期，返回当日有效的规则 | 只读相关的几条 | §5 |
| 3 | 求值：三值求值、同格叠加、区间与待定组；输入里的假设显式带出 | 算对，缺什么说清 | §4 |
| 4 | 反向与差分：要某个效果需要什么、这一跳有哪些效果可争取、改一个事实结果怎么变、库里缺什么 | 知道往哪找、问什么、库外要查什么 | §5 |
| 5 | 回溯：每个输出项到规则、参数引文、条文、口径 | 陈述可核 | §5、§7 |
| 6 | 自检：构建检查、覆盖、金标 | 铲子本身不坏 | §7 |

不属于规则层的：判断点的回答；事实的来源核实；候选结构的生成、分叉、排序；报告措辞；界面；全文检索与向量。去掉的、不必要的（沿用上一版）：精度等级、fallback / priority、指纹追踪、证据通道和挂载列、`credit:<p>`。

## 1. 流程

```text
database/（jurisdiction、doc、clause、param、treaty、decision）
   ▼
写规则（数据而非代码）：rule、variable、predicate、decision、rule_test 五个 csv，只有作者填的列
   ▼
构建 python rule/tools/build.py
   解析 condition，校验引用、效果与槽位、类型、生效期（第 7 节）
   用参考求值器跑 rule_test，全部通过才算构建成功
   覆盖检查：地区 × 主体 × 槽位每格有规则，或数据库里有该格的缺项记录
   写 rule.sqlite（五张表 + 生成列 requires、predicates）、STATUS.md
   ▼
只读函数集（第 5 节）：定位、求值、反向与差分、回溯、字段字典
```

## 2. 表

csv 只有作者填的列；构建生成的列只进 `rule.sqlite`。作者填的文字用英文，引文保持原文。

### 2.1 rule

| 列 | 含义 |
|---|---|
| rule_id | `<地区或地区对>.<slot>.<名>`，如 `cn-hk.outbound_wht.cap_5`；协定规则以 `<来源地>-<对方>` 开头 |
| slot_key | `地区\|主体\|槽位\|流向`。地区 = 规则属于谁的法；主体 = company / individual / all，指收款人（residence 槽位指被判定的人）；流向 = 对方地区代码，`*` 不限。协定规则的地区写来源地（`cn`），流向写对方（`hk`）；同一协定的参数两个方向共用（scope `hk-jp` 的参数既用于 `jp|…|hk` 也用于 `hk|…|jp`，后者香港不征税所以没有规则） |
| condition | 中缀表达式（第 3 节）；无条件写 `true` |
| effect | 效果，按槽位限定（第 2.2 节） |
| overrides | 只有 `deny` 填：被压制的规则 id（分号分隔），或 `cap:*`、`exempt:*`、`share:*`、`exclude:*`、`credit:*`（同一地区、同一流向上所有某类效果；deny 的流向为 `*` 时压制该地区所有流向） |
| procedure | 程序性出处，分号分隔，每项是：证明 / 申报文档的 doc_id（数据库第 7、8 类）、该文档里具体条款的 cite_id（留存材料、申报方式、期限所在的条）、或数据库第 7 类缺项记录的 id（"该地没有申报程序"也是出处）；依赖谓词的 `cap` 规则（协定待遇）必填，其余可填。查询时按项返回原句，不算日期、不排步骤 |
| cite_ids | 条文 cite_id，分号分隔，至少一条来自 law / regulation / treaty |
| decision_ids | 本层 decision 的 id，分号分隔；用了口径才填 |
| effective_from、effective_to | 规则本身的日期（协定适用起始日、MLI 对源泉扣缴生效日）；留空表示跟随所引参数。两者都查：规则日期在期内，且所引参数在求值日全部有效，规则才参与 |
| note | 说明，英文 |

生成列（sqlite）：requires（变量名数组）、predicates（谓词键数组）。

### 2.2 效果与槽位

一条规则一个效果；带参数时写 `<效果>:<param_id>`，参数的 slot 必须等于规则的槽位，单位必须是数值。

| 槽位 | 效果 | 含义 | 方向 |
|---|---|---|---|
| residence | `resident` | 条件成立则该主体是本地区居民 | 不利 |
| outbound_wht、final | `rate:<p>` | 税率 | 不利；有条件的 rate 低于本格无条件的 rate 时是减低税率，按有利处理 |
| outbound_wht、final | `surtax:<p>` | 附加税，税额的 p%（日本复兴特别所得税 2.1） | 不利 |
| outbound_wht | `cap:<p>` | 协定上限，与税率（含附加税）取小；多条成立取最小 | 有利 |
| outbound_wht、inbound、final | `exempt` | 免税，置零 | 有利 |
| inbound | `taxable` | 境外股息计入居民所得 | 不利 |
| inbound、final | `share:<p>` | 按参数比例计入（参数 = 计入比例，%；日本境外股息 5，泰国本地股息 50） | 有利 |
| inbound、final | `exclude:<p>` | 按参数比例不计入（参数 = 不计入比例，%；日本非支配目的股式 20）。法条写的是不计入比例时用它：规则层不做 100 − p | 有利 |
| inbound、restructure | `credit` | 外国税抵免；门槛、层级写在条件里；restructure 格里表示居住地对境外转让税给普通抵免 | 有利 |
| inbound | `credit_underlying` | 间接抵免：抵免还包括付款公司利润已负担的税（内地第 24 条、香港 s50AAAB）；门槛、层级写在条件里；股息是否先还原成税前所得由数据库参数 `<地区>.inbound.underlying_gross_up` 表示 | 有利 |
| final、restructure | `schedule:<p>` | 累进税率表（个人累进表，也包括香港两级税率和日本中小公司税率这类公司分档）；p 是表的第一档税率参数（`<表名>_bracket_1_rate`，一地一类主体一张表，放在 final 槽位，restructure 规则可引用），求值器按表名取整张表。格的税率 = 这笔股息（restructure 格：这笔转让所得）叠在收款方其他应税所得之上的有效税率，读变量 `other_taxable_income` 与 `amount_payee_ccy`（都按收款方地区币种，换算是调用者的事）；二者缺一则 floor 取最低档、ceiling 取最高档，并待定 MISSING。它与 `rate` 是同一个值的备选：有条件的 `rate`（如上市股息 15%、泰国 10% 选择）成立时优先 | 不利 |
| cfc | `include` | 条件成立则未分配利润归入股东 | 不利 |
| cfc | `rate:<p>`、`surtax:<p>`、`schedule:<p>`、`credit`、`credit_underlying` | 归入后股东一侧的税率、附加税、累进表（引 final 槽位的表）和外国税抵免：`credit` 只抵受控公司自己负担的税（日本第 66 条之 7），`credit_underlying` 还抵下层公司的税（内地第 24 条）；只在 include 成立的一侧取用 | 税率不利，credit 有利 |
| exit | `rate:<p>`、`surtax:<p>` | 个人迁出时视同转让持有资产的所得税率；税基按参数 `gain_base`（text）由调用者算。只对个人：迁移公司不在范围内（`目标.md` §6） | 不利 |
| anti_abuse | `deny` | 条件成立则压制 `overrides` 列出的优惠 | 不利 |
| restructure | `rate:<p>`、`exempt`、`cap:<p>`、`credit` | 转让股权的所得税：对转让所得（转让收入 − 成本）的税率；`exempt` 用于协定第 13 条的仅居住国征税、安全港；叠加同 outbound_wht。格的事实里 `target_in_jurisdiction`（被转让公司在本地区）、`transferor_resident`（转让方是本地区居民）由 `eval_transfer` 带入：来源地规则条件写 `target_in_jurisdiction = true and transferor_resident = false`，居住地规则写 `transferor_resident = true` | 不利 / 有利 |
| restructure | `stamp:<p>` | 股权转让印花税，对价（或净资产孰高）的 p%；取用的 stamp 规则相加（双方各付的写两条或一条合计，见 note）；不参与 rate 的叠加，格值里单列 `stamp` | 不利 |
| penalty | `interest:<p>` | 逾期的滞纳金 / 利息 / 附加费，税额的 p%；期间由参数名决定：`_per_day`、`_per_month`、`_per_year`、`_initial` 或 `_once`（一次性）。取用的 interest 规则相加（新加坡 5% 一次 + 每月 1%，香港 5% + 满六个月再 10%）；替代性的档位（日本头两个月的低利率、泰国延期后的 0.75%）不写规则，留作参考参数，规则取的是整段按高利率的上限 | 不利 |
| penalty | `interest_cap:<p>` | 利息合计的上限，税额的 p% | 不利 |
| penalty | `fine:<p>`、`fine_min:<p>`、`fine_max:<p>` | 罚款，税额的 p%（固定，或区间的下限、上限）。格值取所有取用规则的包络：fine_min = 最小，fine_max = 最大。有条件的罚款规则低于同格无条件的罚款时按有利处理（日本自主补缴 5% 对 10%），高于时按不利（偷税、隐匿、过失、未申报的倍数）；条件未答时 floor 是一般情形、ceiling 是更重情形 | 不利；低于无条件者时有利 |

方向决定待定时取哪一侧（第 4 节）。residence 的规则不出税额，出事实（`payer_resident`、`payee_resident`），供其他格的条件读；cfc 格出是否归入，归入时另带股东一侧的税率和抵免标志，由调用者算归入的税。"法律无此规定"不写规则：数据库 `decision` 的缺项记录已引征税范围条款，覆盖检查认它。

每个格的值：outbound_wht = 对股息总额的税率；inbound = 计入比例（没有 taxable 规则取用则为 0）和 credit 标志；final = 税率 × 本格 share / exclude / exempt 之后的计入比例；residence = yes / no；cfc = yes / no，另带 `rate`（归入成立时股东一侧的税率，含附加税）和 `credit`；exit = 对视同转让所得的税率（含附加税）；anti_abuse = 是否压制及压制清单；restructure = 对转让所得的税率（rate / exempt 叠加后）加 `stamp`（印花税率合计），税基按参数 `gain_base` / `stamp_base`（text）由调用者算——转让所得 = 对价 − 成本，对价缺省取净资产份额（有评估报告时取评估值），这两项是输入不是规则；penalty = `{interest: [{param, pct, period}], interest_cap, fine_min, fine_max}`，取用的规则全部累加（新加坡 5% 一次 + 每月 1%），只有 `fine_max` 时 `fine_min` = 0。penalty 格只写一般情形（待遇被否、补税）；偷税、隐匿等更重的倍数留在数据库里作参考参数（`reference_params`）。penalty 格不在 `cells_for_flow` 的九格里，由调用者按需单独求值（`S|all|penalty|*`、`R|all|penalty|*`）。没有 rate 规则取用时 outbound_wht 和 final 的值为空（`-`），表示库里没有这种情形的税率参数（如日本个人收非上市股息的累进税率）。

### 2.3 variable

| 列 | 含义 |
|---|---|
| name | 小写蛇形，全库唯一 |
| kind | `client_fact`（客户事实，缺了待定 MISSING）、`structure`（结构条件：规划时由候选结构决定，未定待定 PLAN；录入已发生的交易时按描述的结构取值，bool 的描述里没有就是假，其他类型缺了仍是 MISSING）、`derived`（由其他变量或其他格算出，不问人；缺输入时待定指向输入变量） |
| type | bool / number / date / text / enum |
| allowed_values | enum 的取值，分号分隔 |
| inputs | 只有 derived 填：它由哪些变量算出，分号分隔；求值时它缺值且输入也缺，needs 指向缺的输入 |
| question | 问客户的话，英文 |
| meaning | 相对于被求值的那笔款，这个变量指什么、通常从哪里来（如 "ratio of the payer's shares held by the payee; shareholder register"）；derived 写算法 |

现有的 derived 变量：`payer_resident`、`payee_resident`（由流程求值器把居民格的结果带入：T / F，格待定则带入其 needs，该地区没有居民规则则 MISSING 指向变量本身）、`payer_low_tax`（由抽取 / 流程按 meaning 写的算法从参数算出）。`parent_treaty_not_worse` 由流程求值器在 eval_flow 里算，不问客户：取来源地与 payee 所在地、来源地与 parent_jur 这两对协定的股息参数，持股达到 holding_pct_min 取 dividend_rate_reduced，否则取 dividend_rate_other 或 dividend_rate；parent 的持股按 holding_pct × parent_holding_pct / 100 计；parent 一侧不高于 payee 一侧为真，parent 那一对没有股息参数或 parent 就在来源地为假，持股缺且决定税率时待定，needs 指向 holding_pct；事实里已给值时不覆盖（2026-11-03 补上，此前没有程序算它）。抽取和提问的字段字典 = 核心字段（各方、持股、款项）∪ kind 为 client_fact 的变量；不另维护字段表。`mode` 不是变量，是求值模式（record / plan）。

### 2.4 predicate

| 列 | 含义 |
|---|---|
| key | 如 `bo`、`ppt`、`gaar`、`substance`；一个认定问题一个键，不按地区分。答案可以按认定地区给：`键@地区`（如 `gaar@hk`）只用于该地区的格，求值时先找它，再找不带地区的键；同一跳上两地各自认定的问题（内地和香港的反避税）就能分开取值 |
| question | 问法，英文 |
| factors_cite | 官方列举的考虑因素所在条款，分号分隔，至少一条 |
| favourable | yes 或 no：对客户有利的答案。优化层据此排分支，编排器据此决定客户的答案能否关闭分叉 |
| factor_vars | 与该判断相关的事实变量，分号分隔，可空（如 bo 的 `passes_on_within_12m`、`substantive_business`）。它们不进条件——法条说它们是要权衡的因素，不是判定条件——但 `judgment_points` 会把它们连同当前值摆出来；只在这里出现的变量算被读取 |

答案固定为 yes / no / unknown，附依据；谁答、怎么答不在本规范里（第 6 节）。能写成事实的认定不写谓词：受益所有人的安全港（上市、政府、居民个人、被这三类人 100% 持有、持股 100% 的居民母公司）是 client_fact 变量和 `or` 条件，只有剩下的综合判断才是 `pred(bo)`。税务机关的"认为 / satisfied"不是谓词：按条文列出的客观条件写规则，并写一条 decision 说明读法（如 D-hk-1、D-sg-1）。受益所有人的安全港（2018 年 9 号公告第三、四条）这类客观条件同样应写成条件性规则，而不是并入谓词——现有规则没做到，见 §10。

### 2.5 decision（解释口径）

| 列 | 含义 |
|---|---|
| id | `D-<地区或地区对>-<序号>`；一处依据一行，同一 id 可多行 |
| statement | 口径内容和理由，英文；条文可作两读时写明取哪一读、另一读会怎样；推算的日期写明推算过程；没建模的分支（如日本 CFC 的部分合算）写明 |
| cite_id、quote | 依据条文和逐字引文 |

规则通过 `decision_ids` 引口径；口径不替人选，只记录人选了什么。

### 2.6 rule_test

| 列 | 含义 |
|---|---|
| test_id | `<rule_id>.<n>` |
| slot_key、date | 求值的格和日期；`all` 主体的规则用 company 或 individual 的格测 |
| facts | `名=值;名=值`，变量按 variable 表；可加 `mode=plan`（默认 record） |
| answers | `谓词=yes/no/unknown;…`，可空 |
| expect | `<效果> <值> <状态>`：效果 = 被测规则的效果词；值 = 该格 ceiling 侧（不利侧）的值，数值、`yes` / `no` 或 `-`；状态 = 被测规则条件的 `T`、`F`、`U:<needs 键，逗号分隔>`，或 `-` 表示规则在该日不适用。如 `cap 5 T`、`cap 10 U:bo`、`share 100 F`（条件不成立，退回 taxable 的 100）、`rate 20 -` |
| source | 官方算例的 cite_id，或 `authored` |

每条读变量或谓词的规则至少三条测试：成立、不成立、待定。官方算例优先。

## 3. condition 写法

只有一种写法，中缀表达式；csv 和 sqlite 里存文本，程序读入时解析成树。

| 成分 | 写法 |
|---|---|
| 变量 | `holding_pct` |
| 参数 | `$cn-hk.outbound_wht.holding_pct_min` |
| 常量 | `25`、`'company'`、`'2026-01-01'`、`true`（只能在比较的右边） |
| 比较 | `左 >= 右`，运算符 `=`、`!=`、`<`、`<=`、`>`、`>=` |
| 属于 | `左 in ['a', 'b']` |
| 名单 | `listed(cn.cfc.cfc_whitelist, payer_jur)`：参数 `cn.cfc.cfc_whitelist_<payer_jur 的值>` 存在、在期内且为 yes（数据库的名单约定：一国一行 bool） |
| 谓词 | `pred(bo)` |
| 与、或、非 | `and`、`or`、`not`，括号分组 |

四条规则：

1. 比较和 `in` 的两边只能是变量、参数或常量，不做算术；需要计算的量作 `derived` 变量。
2. 优先级 `not` > `and` > `or`；参数以 `$` 开头，`cn-hk` 里的连字符不会歧义。
3. 字符串和日期用单引号，日期 `'YYYY-MM-DD'`；构建按 variable.type 和 param.unit 检查两边类型一致（bool 对 bool，数值对数值，text / enum / date 互通；enum 的常量必须在 allowed_values 里；`<`、`<=`、`>`、`>=` 只用于数值和日期）。
4. 变量在 `variable`，参数在数据库 `param`，谓词在 `predicate`；出错时报 `rule_id`。

## 4. 求值语义

规则层定义含义；求值器只是执行，任何实现都必须通过同一套 `rule_test`。

**值**：`T`、`F`、`U`。`U` 带 `needs`，一个 need 是（kind, key）：

| kind | 来源 | key |
|---|---|---|
| MISSING | client_fact 变量没有值，或有值无出处 | 变量名（derived 缺输入时指向输入变量；输入都在而值没算出来，或所依赖的格该地区没有规则，指向 derived 变量本身） |
| PLAN | structure 变量在规划模式下由候选结构决定，尚未定 | 变量名 |
| DISCRETION | 谓词未答或答 `unknown` | 谓词键 |

**连接**：Kleene 三值。`AND`：有 F 则 F；否则有 U 则 U，needs 取并；否则 T。`OR` 对称。`NOT` 翻转 T/F，U 不变。已知值短路待定：`AND(F, U) = F`，持股不达标时不再问受益所有人。

**叶子**：比较两边有缺值 → U；参数在求值日不在生效期 → 该规则不适用（整条跳过，不是 U）；谓词 yes → T，no → F，否则 U(DISCRETION)；`listed` 的变量缺值 → U，否则按参数存在与否 T / F。

**一个格的叠加**（给定 slot_key、日期、事实、答案）。候选 = 该格主体精确匹配或 `all`、流向精确匹配或 `*` 的规则，在日期内有效。每条求 `cond`，按方向决定取不取：T 取，F 不取，U 在 floor 侧按有利方向、ceiling 侧按不利方向（有利效果 floor 取、ceiling 不取；不利效果反之）。取用的规则按固定阶段叠加：

```text
rate → surtax（×(1 + p/100)）→ cap（取最小）→ share（× p/100）、exclude（× (100 − p)/100）→ exempt（置零）→ credit → deny
```

阶段内可交换；例外是同一格里同一个值的多条规则（`rate` 与 `schedule`、多条 `share`、多条 `exclude`）：条件为 T 的有条件规则胜过 `true` 的；两条有条件的条件都为 T 是 Defect（规则写错了，如枚举互斥没写好）；条件为 U 的有条件规则是备选而不是冲突，两侧都参与：floor 取税最低的备选，ceiling 取税最高的备选，`true` 的那条也是备选之一（有条件的可能全不成立）。没有 `true` 规则时，“没有规则适用”也是备选：对 rate 它的值未知（floor 为空），对 share / exclude 它是全额计入（ceiling 不取）。枚举未知时日本本地股息 50% / 20% 两条同时待定、日本个人上市 15% 与累进表同时待定，都是这种情形。`deny` 取用时，它 `overrides` 的效果不适用。

**跨格顺序**固定：residence（付款方在来源地、收款方在居民地、付款方在居民地）→ outbound_wht（来源地）→ anti_abuse（来源地）→ inbound（居民地）→ anti_abuse（居民地）→ final → cfc。协定规则的条件都含 `payee_resident = true`：收款方在对方地区的居民判定为 F 时整条 F，不参与也不进待定组；U 时带着居民格的 needs 待定。`deny` 跨格起作用：来源地 anti_abuse 压制 outbound_wht，居民地 anti_abuse 压制 inbound 和 final。

**区间与待定组**：结果是 `[floor, ceiling]`。每条 cond 为 U 的规则记一组 `(rule_id, needs)`，一组整体才有意义。只记"还能改变结果"的组：把该规则的决定反过来（只翻它一条，其他待定规则不动）重算，两侧都不变就不记（10% 上限等于法定税率时 bo 不会为它被问；上限高于法定税率的协定和它的 PPT 永远不进待定组）。`deny` 规则的反事实在流程层算：翻它看被压制的格变不变，变了就记在 anti_abuse 格，并同时记到被影响的格（该格状态变 U，needs 并入）。组的代价由规则层之外算。

**本层不补值**：MISSING 不取缺省值，规则层不给任何变量 default；structure 变量在录入模式下按描述的结构取值，这是输入的定义，不是补值。要假设，就把假设当输入传入并声明为假设（§5 的 `assume`），输出项把假设清单原样带出，并给出去掉假设后的结果。

**输出项**：每个格产出一项 `(jur, subject, slot, counterparty, rules_applied{floor, ceiling}, floor, ceiling, status, needs, pending, cite_ids, decision_ids, assumptions)`；status ∈ {T, U, absent}，absent = 该格没有规则；rules_applied 每侧只列决定该侧值的规则（同一个值的备选里没被选中的不列，所以 cite_ids、decision_ids、value_kind 都只跟着真正起作用的规则走）；有 schedule 规则的格另带 schedule_inputs（它读到的两个输入），供回溯核对重算；assumptions = 本项依赖的、声明为假设的输入。数值只来自参数，这是回溯链的起点。

## 5. 函数集：定位、求值、反向、出处

所有函数只读，无副作用，同输入同输出。每个输出都带 cite_ids / param_id，没有裸数字。

**定位与供给**

- `cells_for_flow(S, R, subject)`：一笔股息（付款方地区 S、收款方地区 R、收款方主体）要查的九个格：`S|company|residence|*`（付款方）、`R|主体|residence|*`（收款方）、`R|company|residence|*`（付款方是否也是 R 居民）、`S|主体|outbound_wht|R` 与 `|*`、`S|主体|anti_abuse|R` 与 `|*`、`R|主体|inbound|S` 与 `|*`、`R|主体|anti_abuse|S` 与 `|*`、`R|主体|final|*`、`R|主体|cfc|*`。
- `cell(slot_key, date?)`、`rule(rule_id)`、`by_variable(name)`、`by_predicate(key)`：规则行 + 所引条文正文 + 效果与条件里的参数行（值、单位、引文、生效期）+ 口径行 + procedure 文档；查不到的标 NOT FOUND（`rule/tools/rule_tool.py`）。
- `variables()`、`predicates()`：字段字典（name、kind、type、question、meaning；谓词的 question、factors_cite 全文、factor_vars）（`rule/tools/query.py`）。
- `coverage()`：每格有规则 / 有缺项记录 / 空（STATUS）。
- `reference_params(slot_key)`：该格所在地区（及地区对）、同槽位、没有被任何规则引用的参数——申报期限、证明年度、判断因素的门槛——原样带引文返回；只引不算（`rule_tool.py --slot` 一并返回）。

**求值**

- `eval_transfer(target_jur, home_jur, subject, date, facts, answers, mode, assume?)`：一次股权转让——被转让公司在 target_jur，转让方（subject）在 home_jur——的四个格：转让方在两地的居民格、来源格 `target|subject|restructure|home`、居住格 `home|subject|restructure|target`；facts 分款项（transfer_gain、transferred_pct、consideration）、`target.*`（被转让公司：listed、property_rich_ratio）、`transferor.*`（incorporated_in、managed_in、holding_pct、holding_months）。派生变量 `transferor_resident`、`target_in_jurisdiction`、`payee_resident` 由它带入（`eval.py --transfer`）。
- `eval_cell(slot_key, date, facts, answers, mode, assume?)`、`eval_flow(S, R, subject, date, facts, answers, mode, assume?)`：第 4 节语义；`facts` 分款项、`payer.*`、`payee.*` 三组；`assume` 是 facts / answers 里声明为假设的键，输出项把实际用到的列在 assumptions 里，并附"去掉假设后的区间和状态"（`rule/tools/eval.py --assume`）。输出项还带 `value_kind`：statutory（ceiling 侧只有不读事实、不读谓词的规则取用）/ conditional / none。
- `judgment_points(流或格, date, facts, answers)`：当前输入下卡住结果的谓词——键、问法、考虑因素条文、factor_vars 的当前值、它卡住的规则、答 yes / no 各自的区间和剩余未决项。就是待定组的另一种摆法（`query.py judgment_points`）。

**反向与差分**（`rule/tools/query.py`）

- `requirements(slot_key[, effect] | rule_id)`：某格某效果（或某条规则）的条件树展开——每个叶子带变量的问法、参数的值和引文、谓词的问法和因素——加 procedure 各项原句和该格的参考参数。
- `options(S, R, subject, date)`：这一跳每个格的有利规则及其 requirements。
- `what_if(流或格, 基准输入, 改动)`：改一个或几个事实 / 答案，各格的区间、状态、needs 怎么变。
- `gap(S, R, subject)`：这笔流每个格有多少规则、出现了哪些效果、该槽位允许但没出现的效果、读哪些变量和谓词；没规则的格区分"库里有缺项记录"和"未采集"；协定文本缺的流向标出。没出现的效果可能是法律本无、也可能是没建模，库只按槽位记缺项，`gap` 不替它判断。
- `version()`：规则层计数、rule.csv 哈希、数据库文件数 / 参数数 / 哈希、生成时间。

**出处**

- 规则不存正文；`cite_ids` 指向数据库 `clause`，按需取。`explain` = `cell` / `rule` 的输出。
- `trace(items)`：第 7 节的回溯，逐项 PASS / FAIL（`rule/tools/trace.py`）。
- 数据库重传后重跑构建：引用失效、引文不符、金标不过都会报出。

## 6. 判断点与口径

- **判断点**（predicate）是规则层暴露的接口，不是它回答的问题：每个键固定三值 yes / no / unknown，`unknown` 与未答在求值里相同（U）；每个键带 `factors_cite`，官方考虑因素随手可取。谁答、凭什么答、答案记在哪里，不在本规范里。
- **口径**（decision）是作者写规则时取的读法：条文可作两读、日期要推算、某分支不建模时写一条，规则引它；求值按口径算。口径只记录作者选了什么。范围裁定（某类所得不入模）不写规则。
- **指引和网页**可以引，但 cite_ids 至少有一条 law / regulation / treaty 条文。

## 7. 完整性与校验

构建时出现下面任何一项都报错：

1. condition 不能解析，或引用的变量不在 `variable`、参数不在数据库 `param`、谓词不在 `predicate`、口径不在 `decision`；比较两边类型不一致；`listed` 的前缀在 `param` 里没有任何参数；
2. effect 不在该槽位允许之列；效果参数不在 `param`，其 slot 与规则槽位不符，或不是数值；`cite_ids` 为空、不在 `clause`，或没有一条来自 law / regulation / treaty；`procedure` 既不是 `doc` 也不是第 7 类缺项记录；
3. `slot_key` 不是四段，或地区、主体、槽位、流向取值不合法；流向为地区时数据库 `treaty` 里没有这一对带文本的行；协定规则的 id 不以地区对开头；
4. 依赖谓词的 `cap` 规则没有 `procedure`；`deny` 没有 `overrides`，非 `deny` 有；`overrides` 指向的规则不存在、不在同一地区或流向不相容；
5. 规则日期与所引任一参数的生效期无交集；日期格式不是 YYYY-MM-DD；
6. 口径引文不在所引条款里；变量名不合法、重复，kind / type 不合法，question 或 meaning 为空，derived 没有 inputs 或 inputs 不是变量；谓词键重复、factors_cite 为空或不在 `clause`；变量无规则读；csv 有规范之外的列；
7. `rule_test` 任一条不过，或读变量 / 谓词的规则没有 T、F、U 三条测试；测试里的事实不是变量、答案不是谓词或不是三值之一。

**覆盖**：地区 × {公司, 个人}（按 jurisdiction 的 in_scope 列）× 6 槽位，每格要么有规则，要么数据库 `decision` 里有该格的缺项记录（subject + slot）。空格列在 STATUS，不算错误。

**运行时不变量**（求值器必须检查，违反即 Defect）：floor ≤ ceiling；状态 T 的项没有 needs；取用了规则的项至少一条 cite；同一流同一格只有一项。按参数重算等于输出值由叠加函数的确定性保证。

**回溯**：`rule/tools/trace.py` 对每个输出项走 项 → rule_id 在 rule 表 → 效果与条件参数在 `param`、`param.quote` 逐字在 `clause.text` 里、参数在求值日有效 → `cite_ids` 条款存在且所属文件在求值日有效 → decision_ids 的引文逐字在条款里 → 按取用的规则和参数重算等于输出值；任何一环断掉即 FAIL。输入是 `eval.py --json` 的输出文件，或直接给 `--slot` / `--flow` 现算现核。

## 9. 写法示例

内地向香港公司付股息（数据库里已有参数）：

```text
rule_id                     slot_key                    condition                                                                                 effect                                        overrides  procedure
cn.outbound_wht.statutory   cn|company|outbound_wht|*   true                                                                                      rate:cn.outbound_wht.dividend_wht_rate        —          —
cn-hk.outbound_wht.cap_10   cn|all|outbound_wht|hk      payee_resident = true and pred(bo)                                                        cap:cn-hk.outbound_wht.dividend_rate_other    —          cn.sta.2019-35
cn-hk.outbound_wht.cap_5    cn|company|outbound_wht|hk  payee_resident = true and holding_pct >= $cn-hk.outbound_wht.holding_pct_min and pred(bo)  cap:cn-hk.outbound_wht.dividend_rate_reduced  —          cn.sta.2019-35
cn-hk.anti_abuse.ppt        cn|all|anti_abuse|hk        payee_resident = true and $cn-hk.anti_abuse.ppt_applies = true and pred(ppt)              deny                                          cap:*      cn.sta.2019-35
```

两条 cap 都取用时取最小。bo 待定：floor 两条 cap 都取（5%），ceiling 都不取（10% 法定）。待定组只有 `(cap_5, {bo})`：cap_10 等于法定税率，翻它结果不变，不记。ppt 待定：floor 不压制，ceiling 压制；翻 ppt 会把 floor 从 5 变成 10，所以 `(ppt, {ppt})` 记在 anti_abuse 格并并入 outbound_wht 格。收款方是否香港居民先由 `hk|company|residence|*` 判出，derived 变量 `payee_resident` 为 F 时三条协定规则整条 F。

日本公司收境外股息（`jp|company|inbound|*`）：`$jp.inbound.foreign_dividend_taxable = true → taxable`；`holding_pct >= $jp.inbound.exemption_holding_pct_min and holding_months >= $jp.inbound.exemption_holding_months_min → share:jp.inbound.exemption_expense_share`（计入 5%）；`true → credit`。三条共存：taxable 是基数，share 乘上去，credit 抵免。

日本公司收本地股息（`jp|company|final|*`）：`domestic_dividend_class in ['wholly_owned', 'affiliated'] → exempt`、`= 'other' → exclude:…share.other`（不计入 50）、`= 'noncontrolling' → exclude:…share.noncontrolling`（不计入 20，即计入 80）。类别未知时三条都待定，floor 取 exempt 的 0，ceiling 取 23.2 不减。

泰国–越南协定（`th|all|outbound_wht|vn`）：`payee_resident = true and pred(bo) → cap:th-vn.outbound_wht.dividend_rate`（15%），默认 `rate:th.outbound_wht.dividend_wht_rate`（10%）。上限高于法定税率，反事实判据下这条和它的 PPT 都不会进待定组。

## 10. 构建与交付

- 先 `python database/tools/build.py`，再 `python rule/tools/build.py [--root rule/] [--db database/]`；错误退出码 1。
- `python rule/tools/eval.py --slot <slot_key> --date YYYY-MM-DD --facts 'a=1;b=x' --answers 'bo=yes' [--mode record|plan] [--json]`：一个格；`--flow <付款方地区> <收款方地区> <主体>` 加 `--facts 'payer.incorporated_in=cn;payee.incorporated_in=hk;holding_pct=30'`：一笔股息的九个格（输出八项，付款方在 R 的居民格只用来算 `payer_resident`）。
- `python rule/tools/trace.py --items out.json`（或 `--flow` / `--slot` 同 eval 的参数）：回溯核对。
- `python rule/tools/rule_tool.py --slot <slot_key> [--date] | --rule <rule_id> | --variable <名> | --predicate <键> [--brief] [--json]`。
- `python rule/tools/query.py judgment_points | requirements | options | what_if | gap | variables | predicates | version | cells_for_flow …`（参数同 eval；`what_if` 加 `--set 'k=v'`、`--answer-set 'k=v'`；`requirements` 用 `--slot [--effect]` 或 `--rule`）。
- `schedule` 规则的 requires 自动含 `other_taxable_income`、`amount_payee_ccy`；penalty 槽位的金标 expect 写该条规则自己的数（`interest 0.05 T`），因为格的值是字典。
- 产物：`rule.sqlite`（五张表 + requires、predicates；列表列存 JSON 数组）、`STATUS.md`（计数、错误、金标结果、覆盖空格、无测试的规则）。
